## 仮実装・仮の値

- すべての名前・説明文は仮（「（仮）」付き）。世界設定・主人公・メインストーリーは未確定
- 最初の世界のテーマは依頼書の例「頑張ったのに誰にも褒めてもらえなかった悔しさ」を仮置き
- 属性4種・状態異常3種は仮の体系
- ランクは5段階で仮置き（倍率・必要素材も仮）。ランクアップ時の上限レベル制などは未検討
- 数値（能力値・成長・経験値曲線・加入率・ドロップ率）はすべて仮。`data/balance.json` と各データで調整
- 画像はすべて自動生成の仮画像（データの `image` にパスを書けば差し替わる）
- 街の主要施設（宿屋・ショップ・工房・酒場・住民・街探索・街の外）は実装済み。文章・品ぞろえ・イベント内容は仮
- 人間キャラクターの入手方法は未確定（現在は開始時とデバッグのみ）
- 戦闘の数値（防御定数50、乱数幅±5%、制限時間5分、回復量＝攻撃力×威力）はすべて仮
- 味方は先頭の敵を集中攻撃、敵はランダムに狙う。ボス部位が本体より前なら部位を優先する（ターゲット指定は未実装）
- 探索の数値（出会う確率、行動力・時間のコスト、1時間帯=3tick、宿代10G、経験値のレベル補正）はすべて仮
- 加入は1戦闘1体まで・種類ごとに1回判定（仮の決定）。加入時のレベルは倒した敵のレベル
- 経験値は生き残った味方全員に全額（分配しない）。倒れた味方は0
- 全滅時は街へ戻りHP1（仮。所持金などのペナルティなし）
- ドロップの品質は補正なしで抽選（敵の強さ・天候による補正は未検討）
- 「探索する」で何も起きない確率がある（仮）
- ショップの品ぞろえ・価格、強化費用、レシピ、イベントの文章はすべて仮
- ボスの強さは「Lv3では勝てず、Lv6前後から勝てる（全快時）」を目安に仮調整。連戦後はもう少し高いレベルが必要
- ボスの特殊加入条件は「BREAK1回以上＋部位破壊1つ以上で撃破」で確率100%（仮）
- 部位は本体より前に並ぶので、味方は必ず部位から攻撃する（ターゲット指定がないため）。部位を無視して本体を狙う手段は未検討
- 人間キャラクターの入手方法は引き続き未確定（酒場で仲間になる、などが候補）

## 既知の課題・改善点

- 画面の通しテスト（`npm run e2e`）は Playwright を一時的に入れて実行する方式（依存ゼロ方針のため `npm test` には含めない）
- 想定外の例外はトーストで通知するだけ。エラーの自動報告の仕組みはない
- 図鑑のモンスター番号はデータの並び順。世界が増えたら世界ごとの番号にするか検討
- モンスターデータの `codexStages` は検証していない（`balance.codex.monsterStages` は検証済み）
- 重複入手の変換は即時。演出（「○○は魂の結晶になった」）は Phase 5 の加入演出と合わせて作る
- HPはフィールドで持ち越し（宿屋・消耗品で回復）に決定。全滅時の扱いは仮
- 戦闘画面では名前の長いユニットが省略表示になる（仮名の「（仮）」も幅を取っている）
- ターゲット指定を追加する前に、`src/battle/engine.js` の味方先頭・敵ランダムという対象決定を方針関数へ分離し、既定挙動の再現テストを維持する
- 状態異常は現在、同じ効果の再付与で残り時間を更新し、スタックしない。将来スタック型を追加する場合は `maxStacks` 等の上限をデータ検証で必須にする
- E2EはPlaywrightを一時導入する方式。TASK_001の実行環境ではChromium配布先への通信制限でブラウザ取得に失敗したため、ローカルE2Eは未確認（公開版の主要導線はブラウザで手動確認済み）
