# モンスター追加標準ガイド

この文書は、『思想世界RPG』へモンスターを追加するときの標準ワークフローです。
今後の依頼で「`monster-development-guide.md` に従って追加」と指定された場合、Codexは依頼文へ共通仕様が再掲されていなくても、本ガイドとリンク先の現行実装を確認して作業します。

詳細なデータ形式は [content-guide.md](content-guide.md)、戦闘の正式仕様と利用可能な条件・効果は [battle-system.md](battle-system.md)、現在の実装状況は [HANDOFF.md](HANDOFF.md) を正とします。内容が食い違う場合は、実コードとデータを確認し、独断で仕様を変更せず報告してください。

## 1. 作業開始時の確認順

1. `AGENTS.md` と本ガイドを読む。
2. `docs/HANDOFF.md`、`docs/TODO.md`、`docs/battle-system.md`、`docs/content-guide.md` を確認する。
3. `data/monsters.json`、`skills.json`、`passives.json`、`statuses.json`、`markers.json`、`species.json`、`elements.json` を検索する。
4. 同じ強さ帯・戦闘タイプの既存モンスターと、ソメイム `mon_007`、イロワン `mon_008` の実装を必要な範囲で比較する。
5. 図鑑、加入、エンカウント、画像表示、ランク・レベル習得、関連テストの現在のコードを確認する。

引き継ぎ文書だけを根拠にせず、必ず現在のJSON・コード・テストと照合します。

## 2. 変更してはいけない共通仕様

- モンスターは原則すべて仲間にできる。
- 人間キャラクターと同じ3体パーティへ編成できる（戦闘は3対3）。
- コンテンツは可能な限り `data/` のJSONで追加する。
- 表示名ではなく、変更しない固定IDを参照する。
- 既存の条件・効果・状態・マーカー・パッシブを最優先で再利用し、同じ概念を別IDで二重実装しない。
- モンスター固有の名前やIDで戦闘エンジンを分岐させない。
- ユーザーが指定した固有設定・数値を、重大な矛盾なしに勝手に変更しない。
- 主人公、メインストーリー、PvPなど、依頼外の大規模仕様を追加しない。

## 3. 戦闘の基準

**1ターン = そのユニットが1回行動すること**です。味方と敵の全員が一巡する意味ではありません。

| 値 | 増える条件 | 主な用途 |
|---|---|---|
| `turnCount` | 攻撃・回復・防御・待機など、そのユニットが行動したとき | `durationTurns`、特定ターン条件 |
| `attackCount` | 攻撃として成立した行動 | 「2の倍数」「3回ごと」などの攻撃回数条件 |

- 攻撃行動はターンと攻撃回数が進む。
- 非攻撃行動はターンだけ進み、特技に `"countsAsAttack": false` を指定する。
- `durationTurns` は効果を受けたユニット自身の行動回数で減少する。
- 攻撃回数条件に `turnCount` を使わない。
- コンボや同一行動内の追加攻撃は、明示された既存効果に従い攻撃回数を余分に増やさない。

詳細は [battle-system.md の「ターン」の正式定義](battle-system.md#ターンの正式定義) を参照してください。

## 4. モンスターデータ

基本登録先は `data/monsters.json` です。世界別にファイルを分ける場合は `data/manifest.json` へ登録します。

- `id`: 既存最大番号の次となる `mon_XXX`。使用済みIDを変更・再利用しない。
- `worldId`、`element`、`speciesIds`: 既存の固定IDを参照する。
- `speciesIds`: 複数指定可能。表示名の部分一致では判定しない。
- `baseStats`、`growth`: 強さ、戦闘タイプ、能力内容と同程度の既存モンスターを基準に調整する。
- `learnset`: ランクとレベルのAND条件。最大10特技。
- `passives`: 基本1～2個。特技セット枠には含めない。
- `recruit`: 原則必須。指定がなければ同じ強さ帯を基準に加入率・失敗補正・確定回数を決める。
- `drops`、`exp`、`gold`: 指定がなければ同じ強さ帯を基準に決める。
- `elementMultipliers`: 現在の属性IDと同強度帯を確認して設定する。

指定されていない基礎ステータス、成長値、経験値、ゴールド、加入率、ドロップ率、MP消費などは、不要な確認質問を増やさず合理的に補完し、完了報告へ記載します。

## 5. 特技・パッシブ・状態・スタック

### 特技

- 1体につき最大10個を習得し、その中から最大5個を戦闘用にセットする。
- セット順が発動優先順位になる。全習得特技を自動使用させない。
- ランク＋レベルの習得条件は `learnset` に記録する。
- 攻撃回数、特定ターン、確率、HP、状態、被ダメージ、即時発動、連携発動などは、[battle-system.md](battle-system.md) に掲載された既存の汎用条件・効果を使う。
- ダメージは共通ダメージ計算へ、乱数は `battle.rng`／`src/core/rng.js` へ統合する。独自計算式や `Math.random()` を特技内へ書かない。

### 固有パッシブ

- 基本1～2個。
- 5つの特技セット枠には含めない。
- 既存の `PASSIVE_EFFECTS` で表現できるものを再利用する。

### 状態・蓄積マーカー

- 既存の状態・マーカーがある場合は、その固定IDを再利用する。
- `marker_001`「侵色」を使う新モンスターのために、別の侵色を作らない。
- `marker_002`「犬の好意」は犬族 `species_003` 共通。犬族ユニットごとの個別保持で上限10。犬族だから自動増加するわけではなく、利用能力を持たない犬族がいてもよい。
- 新規マーカーには必ず `maxStacks` を設定する。種族限定なら `allowedSpeciesIds` を指定する。
- ターン継続は `durationTurns`、処理タイミングは必要に応じて `turnTiming: "actionStart"` / `"actionEnd"` を使う。

### 既存機能で表現できない能力

モンスター名やモンスターIDを判定する専用 `if` 文は原則追加しません。必要な範囲だけ、別のモンスターや人間キャラクターもJSONから利用できる汎用の条件・効果・状態種別・パッシブ効果として登録します。将来用途だけを想定した大規模な抽象化は行いません。

## 6. 画像

- 依頼時の添付画像を正式画像として使用し、デザインを再生成・改変しない。
- 正式モンスター画像は、元デザイン・全身・縦横比を維持して背景だけを除去した実透過PNGを原則とする。
- `img/monsters/mon_XXX.png` の命名規則に合わせ、モンスターデータの `image` から参照する。
- 市松模様が画像自体に焼き込まれている場合は透過ではないため、背景除去の結果を目視確認する。
- 一覧、編成、図鑑、戦闘画面とスマートフォン縦画面で、切れ・潰れ・縦横比崩れ・はみ出しを確認する。

## 7. 図鑑・加入・出現場所

- 新モンスターは既存図鑑へ自動連携させ、未発見→発見→撃破→仲間→調査の段階解放を維持する。
- 個別の追加段階が不要なら、共通の `balance.codex.monsterStages` を使用する。
- `recruit` を登録し、原則仲間にできるようにする。ボスだけは既存の特殊加入方式を使用できる。
- `encounters.json` の既存地点へ配置する。正式地点が未確定なら、後からID参照だけで移動できる仮配置にする。
- 図鑑の生息地・ドロップ・加入情報は既存データからの逆引きを利用する。

## 8. ユーザー指定の扱い

依頼で明示された次の項目を最優先します。

- 名前、所属、テーマ、強さ、属性、種族、戦闘タイプ
- パッシブ、特技、発動条件、倍率、スタック数、ターン数
- 習得ランク・レベル、画像、出現場所、加入率など

強すぎる・弱すぎる可能性だけを理由に変更しません。実装結果が大きく分岐する曖昧さ、既存仕様との重大な矛盾、セーブ破損につながる問題がある場合だけ確認し、それ以外は既存バランスから補完します。

## 9. 標準実装手順

1. 既存IDと再利用可能な条件・効果・状態・マーカーを検索する。
2. モンスター、特技、パッシブ、必要な状態・マーカー・種族をJSONへ追加する。
3. 画像を配置し、`image` を登録する。
4. エンカウントへ配置し、加入・ドロップ・図鑑逆引きが成立するようにする。
5. ランク・レベル別の習得と最大5枠セットを確認する。
6. 新能力の再発防止テストを追加し、既存モンスターへの回帰影響を確認する。
7. `npm run validate`、`npm test`、`npm run check` を実行する。
8. UIを変更した場合は可能な範囲で `npm run e2e` とスマートフォン縦画面を確認する。
9. 指定されていない補完値、仮配置、確認できなかった項目を完了報告へ明記する。

## 10. テストの最低基準

- 新しい発動条件、効果、パッシブ、状態、マーカーの正常系・上限・不成立条件。
- seed固定乱数を使う能力の再現性。
- ターンと攻撃回数、`countsAsAttack`、`durationTurns` の分離。
- ランク＋レベルによる習得、最大10習得・最大5セット。
- 加入、図鑑、エンカウント、画像パスなどの参照切れ。
- 既存のソメイム、イロワンおよび共通戦闘機能を壊していないこと。

標準コマンド:

```sh
npm run validate
npm test
npm run check
```

## 11. 短縮依頼テンプレート

すべての項目は必須ではありません。不足部分は、既存ゲーム仕様と同じ強さ帯のモンスターから合理的に補完します。

```text
monster-development-guide.mdに従って追加

名前：
所属：
強さ：
属性：
種族：
戦闘タイプ：
テーマ：

パッシブ：
・

特技：
・

画像：
添付画像

その他：
```

最短なら、次の形式でも依頼できます。

```text
monster-development-guide.mdに従って追加
名前：○○
強さ：1
テーマ：○○
パッシブ・特技：添付の設定どおり
画像：添付画像
```

## 12. 完了報告

最低限、次を報告します。

- 実装した内容
- 最終ステータス、特技・パッシブ、MP消費、加入率、出現場所
- 指定されていない部分をCodex側で決めた値
- 新しく追加した汎用機能（ある場合）
- 変更ファイルと追加テスト
- `validate`、`test`、`check`、実施したE2E・画面確認の結果
- 未実装、仮実装、確認できなかった項目
